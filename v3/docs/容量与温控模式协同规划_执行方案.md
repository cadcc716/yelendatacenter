## 0. 一页概览

### 0.1 要做什么

现模型（全自适应）：每个典型日各自优化一条 24 h 液冷温区序列。
新模型（K-模式）：规划时同时决定容量 **x** 和 **K 条日温区序列（温控模式库）**；运行时每天从库里选成本最低的一条，档位、冷源、储能等连续量仍逐日优化。

论文输出因此从"一组容量"变为"一组容量 + 一份可执行的温控预案库"。

## 1. 数学模型（写入论文第 3、4 章的内容）

### 1.1 记号

- 典型日 $s\in\mathcal S$，经验概率 $p^0_s$，模糊集 $\mathcal P$（综合范数，半径 $\theta_1,\theta_\infty$，与现稿式 (31) 相同）。
- 温区 $j=1..J$（J = 5），时段 $t=1..T$（T = 24）。
- **温区模式** $\omega$：0-1 矩阵 $u^\omega_{jt}$，$\sum_j u^\omega_{jt}=1$。
- $Q_s(\boldsymbol x;\omega)$：容量为 $\boldsymbol x$、第 $s$ 日温区序列固定为 $\omega$ 时的日运行成本。温区固定后，漏电、自然冷却系数、冷机 COP、热泵 COP、安全档位集合都是常数，$Q_s(\boldsymbol x;\omega)$ 是线性规划的最优值；不可行时记为 $+\infty$。

### 1.2 K-模式分布鲁棒模型

$$
F_K=\min_{\boldsymbol x\in\mathcal X,\ \omega^1,\dots,\omega^K}\ \boldsymbol a^\top\boldsymbol x+365\max_{\boldsymbol p\in\mathcal P}\sum_{s}p_s\min_{k\in[K]}Q_s(\boldsymbol x;\omega^k)
$$

$\boldsymbol a$ 为能源侧设备年化单价（不含 GPU，与现稿第二步口径一致）。

### 1.3 命题 1：等价 MILP（模式一致性约束）

引入模式变量 $u^k_{jt}\in\{0,1\}$、分配变量 $z_{sk}\in\{0,1\}$，把现模型的日温区变量 $u_{sjt}$ 松弛为 $[0,1]$ 连续变量，并加入：

$$
\sum_j u^k_{jt}=1,\qquad \sum_k z_{sk}=1
$$
$$
u_{sjt}-u^k_{jt}\le 1-z_{sk},\qquad u^k_{jt}-u_{sjt}\le 1-z_{sk}\qquad\forall s,k,j,t
$$

其余约束与现稿式 (1)–(29)、式 (40) 完全相同。$z_{sk}=1$ 时 $u_s=u^k$，所以 $u_s$ 自动取整数。

对称性破除（模式按平均温区排序）：

$$
\sum_{j,t}j\,u^k_{jt}\le\sum_{j,t}j\,u^{k+1}_{jt},\qquad k=1,\dots,K-1
$$

**定温设计**（传统做法的对照）：K = 1，并加 $u^1_{jt}=u^1_{j1}\ \forall t$。

### 1.4 命题 2：自适应层级

$$
F^{\text{定温}}\ \ge\ F_1\ \ge\ F_2\ \ge\ \cdots\ \ge\ F_{|\mathcal S|}=F_\infty
$$

$F_\infty$ 即现稿的全自适应模型（S5）。证明：可行域逐级包含。

**自适应价值**：${\rm VoA}_K=(F_K-F_\infty)/F_\infty$。

### 1.5 模式池上的选址主问题（算法用）

给定候选模式池 $\Omega$（其中每个模式的 $\bar u^\omega_{jt}$ 是已知常数），引入 $v_\omega\in\{0,1\}$（模式是否入库）、$z_{s\omega}\in\{0,1\}$（日—模式分配）：

$$
\sum_\omega v_\omega\le K,\qquad z_{s\omega}\le v_\omega,\qquad \sum_\omega z_{s\omega}=1,\qquad u_{sjt}=\sum_\omega z_{s\omega}\bar u^\omega_{jt}
$$

每天只有一份运行约束，不需要大 M。0-1 变量只有 $|\Omega|+|\mathcal S||\Omega|$ 个。主问题的最优值是 $F_K$ 的上界，模式池扩大时单调不增。

去掉基数约束（K = |S|），同一主问题就求解全自适应模型。

### 1.6 命题 3：对任意 K 有效的下界

为每天引入容量副本 $\boldsymbol X_s$（约束 $\boldsymbol X_s=\boldsymbol x$），对任意乘子 $\boldsymbol\pi_s$（符号不限）和任意 $\hat{\boldsymbol p}\in\mathcal P$：

$$
LB(\boldsymbol\pi,\hat{\boldsymbol p})=\sum_s D_s+\sum_c\min\{0,\ a_c-\textstyle\sum_s\pi_{sc}\}\,\bar x_c\ \le\ F_\infty\ \le\ F_K
$$

$$
D_s=\min_{\boldsymbol X_s\in[0,\bar{\boldsymbol x}],\ \omega,\ \boldsymbol y}\ \Big\{365\,\hat p_s\,C_s(\boldsymbol y)+\boldsymbol\pi_s^\top\boldsymbol X_s\Big\}
$$

$D_s$ 是"带容量租金的单日规划 MILP"（温区放开）。证明两步：先用 $\max_{\boldsymbol p}\ge\hat{\boldsymbol p}$，再对 $\boldsymbol X_s=\boldsymbol x$ 做拉格朗日松弛。

`UB − LB` 同时包含求解误差和自适应损失，是保守间隙。

### 1.7 样本外策略

对任意一天 $d$（365 个历史日或其他年份）：逐个模式求 $Q_d(\boldsymbol x;\omega^k)$（K 个 LP），取最小者执行。全部 K 个都不可行的日子记为"预案失效日"，单独统计，并用全自适应 MILP 补算其成本。

### 2.4 各函数的实现要点

**(a) `modes.mode_of(R)`**：`np.rint(R["u"]).astype(int)`，形状 (5, 24)。`key(U)=U.tobytes()` 用于去重。`const_modes` 生成 5 个全天同一温区的模式（既是定温基线，也保证任何一天至少有一个可行模式）。

**(b) `mode_lp.lp_fixed`**：仿照 `ccg_solve.mono` 建模，区别只有三处：

1. 每天先建容量副本 `Xs`（除 N 外各设备一个变量，界 [0, xmax]，目标系数 0；N 为固定值变量），记录连接行 `Xs[c] − X[c] = 0` 的行号；
2. `add_day(M, P, Xs, day, flags, w=0.0, Tamb_des=Td, u_mode=U_s)`；
3. DRO 对偶行原样照抄 `mono` 中的 `lam、pi、mu、nu` 四组变量与三组约束。

返回 `x`、各日 `Q`、目标值、`pi[s][c]`（连接行对偶）。求解后跑 `simul_check`；若出现同时充放，这一轮的对偶照用，目标值用加回 0-1 变量后的重解结果。

**(c) `mode_lp.day_cost`**：`add_capacity(fix=x)` + `add_day(u_mode=U, w=1.0)`，LP。不可行返回 `np.inf`。

**(d) `select_master.select`**：`build_master` 的写法，但 `add_day(..., u_int=False)`；然后：

```python
W = len(pool); U = np.stack(pool)                       # (W, J, T)
v  = M.var(W, 0, 1, integer=True)
zz = M.var((S, W), 0, 1, integer=True)
M.con([(zz[:, w], 1.0) for w in range(W)], lo=1.0, hi=1.0)     # 每天选一个模式
M.con([(zz, 1.0), (v[None, :], -1.0)], hi=0.0)                 # 只能选入库模式
M.row([(v, 1.0)], hi=float(K))                                 # 至多 K 个
for s in range(S):
    u = Vs[s]["u"]
    for j in range(J):
        M.con([(u[j], 1.0)] + [(zz[s, w], -U[w, j].astype(float)) for w in range(W)], lo=0.0, hi=0.0)
```

再加 `mono` 的 DRO 对偶行。为控制规模，可事先用 `day_cost(ctx, xmax, day, U)` 剔除对某天不可行的 (s, w) 组合（把对应 `zz` 上界设 0）。**必须给热启动**（上一轮或 (d′) 得到的 `x`、分配和运行解）；预试算中不给初始解时 HiGHS 在 120 s 内找不到好解。

**(d′) 快速选址：成本矩阵与 LP 交替（默认使用，预试算已验证）**

```
输入：模式池 pool（W 个），K，初始容量 x
重复：
  1  成本矩阵 C[s, w] = day_cost(ctx, x, s, pool[w])          # S×W 个单日 LP，每个约 0.1 s
  2  固定 x，选 K 个模式使  inv(x) + 365·max_p Σ_s p_s·min_{w∈选中} C[s, w]  最小
       W 取 K 的组合数 ≤ 5 万：直接枚举，每个组合调用一次 worst_p
       否则：解一个不含运行约束的小 MILP（变量 v_w、zz_sw，Q_s = Σ_w zz_sw·C[s, w]，加 DRO 对偶行）
  3  每天分配给选中模式里成本最低的一个 → lp_fixed 重新优化容量，得到新 x 和目标 f
直到 f 不再下降
```

每一步目标都不增，通常 2–3 轮收敛。它是块坐标下降，可能停在局部解，所以起点要多试几个：上一个 K 的解、K − 1 的解加一个新模式、各单一模式的最优解。

**(e) `kadapt_mono.solve_k`**：`add_day(..., u_int=False)`，然后：

```python
uk = M.var((K, J, T), 0, 1, integer=True)
for k in range(K):
    M.con([(uk[k, j], 1.0) for j in range(J)], lo=1.0, hi=1.0)

M.con([(z[:, k], 1.0) for k in range(K)], lo=1.0, hi=1.0)

        M.con([(uk[k], 1.0), (Vs[s]["u"], -1.0), (z[s, k], 1.0)], hi=1.0)
jw = (np.arange(J)[:, None] * np.ones(T)).ravel()
for k in range(K - 1):                                   # 对称性破除
    M.row([(uk[k], jw), (uk[k + 1], -jw)], hi=0.0)
if const:                                                # 定温
    for k in range(K):
        M.con([(uk[k][:, 1:], 1.0), (uk[k][:, :1], -1.0)], lo=0.0, hi=0.0)
```

K = 1 时更简单：建一个 `u1`，所有天 `add_day(..., u_var=u1)`。

**(f) `mode_gen.best_response(ctx, x)`**：就是 `ccg_solve.solve_sub`（固定容量逐日 MILP），返回各日 `Q` 和 `mode_of(R)`。同时给出精确上界 `inv + 365·worst_p(Q)·Q`。

**(g) `mode_gen.rent_pricing(ctx, pi, phat)`**：逐日建 MILP：容量副本 `Xs` 为自由变量（界 [0, xmax]，N 固定），目标 = `Σ_c pi[s][c]·Xs[c] + 365·phat[s]·Q_s`（`add_day` 的 `w=365*phat[s]`），温区 `u` 为 0-1。返回 `mode_of`、最优界 `M.dual_bound`（作 $D_s$）、`Xs` 的取值（次梯度用）。

**(h) `mode_gen.consensus(ctx, x, cluster, phat)`**：一个共享 `u1 = M.var((J,T),0,1,integer=True)` 加 $\sum_j u1=1$；对簇内每天 `add_capacity(fix=x)` 后 `add_day(..., u_var=u1, w=365*phat[s])`。120 个 0-1 变量。返回新模式。第二个变体把 `fix=x` 换成带租金的自由副本（探索用）。

**(i) `lower_bound.lb`**：

```python
LB = sum(D_s for s) + sum(min(0.0, a[c] - sum(pi[s][c] for s)) * xmax[c] for c in energy_caps)
```

`D_s` 必须取 MILP 的最优界而不是可行解目标值。

**(j) `lower_bound.subgrad`**：保持 $\sum_s\pi_s$ 不变的次梯度步：

```python
g[s] = Xs_opt[s] - mean_over_s(Xs_opt)          # 各设备分量
tau  = rho * (UB - LB) / sum(g**2)               # rho 初值 1，连续 3 次无改进则减半
pi[s] += tau * g[s]
```

最多 20 轮，记录历史最大下界。初值优先用 `lp_fixed` 的对偶；若该初值下界很差，改用 `pi[s][c] = a[c]·p0[s]`。

**(k) `mgs.run` 主循环**：

```
输入：ctx, K, 初始模式池 pool0
1  pool ← pool0 ∪ 5 个常值模式
2  重复：
3      (x, 分配, 目标) ← 快速选址 (d′)；每隔 3 轮或收尾时用 select 主问题 MILP 带热启动核对   # 上界
4      (Q, 模式_BR, UB_exact) ← best_response(ctx, x)          # 仅 K=∞ 时用 UB_exact 作上界
5      (pi, ·) ← lp_fixed(ctx, 选中的模式)；phat ← worst_p(Q_选中)
6      模式_RP, D, Xs ← rent_pricing(ctx, pi, phat)；LB ← max(LB, lb(...))
7      对每个簇 k：模式_CS ← consensus(ctx, x, 簇k, phat)
8      把 模式_BR、模式_RP、模式_CS 中的新模式加入 pool
9  直到：没有新模式，或主问题目标连续 2 轮改进 < 0.02%，或达到 15 轮
10 （可选）subgrad 强化下界
输出：x、K 个模式、分配、UB、LB、历史记录、池大小、用时
```

K < |S| 时，上界取主问题目标（它本身就是 K-模式可行解的精确目标）；`best_response` 的模式只进池，不直接当上界。

**(l) `oos_policy.evaluate`**：仿照 `oos_test.py` 用 `multiprocessing.Pool`；任务粒度为 (日, 模式)。每天输出：选中的模式编号、日成本、缺额、超期、购电、碳排放、最高气温；全不可行的日子标记 `fail=1`，再用原 `oos_test.one` 的全自适应 MILP 补算。

## 7. 风险与预案

| 风险 | 表现 | 处理 |
|---|---|---|
| 自适应价值很小 | ${\rm VoA}_1<0.3\%$ | 走路线 B（见 G2） |
| 下界不紧 | (UB − LB)/UB > 1% | 次梯度 20 轮；仍不行则如实报告为保守下界，并用紧凑 MILP 的界作补充 |
| 小 K 时主问题不可行 | 某天在池内无可行模式 | 池中始终保留 5 个常值模式；仍不可行则检查该日 `day_cost` 的不可行原因 |
| 模式池膨胀 | 主问题变慢 | 连续 3 轮未被选中的模式移出池（常值模式除外）；预先剔除不可行的 (日, 模式) 组合 |
| 紧凑 MILP 在 K = 3 求不动 | HiGHS 到时限间隙仍大 | 只把 K = 1、2 作为核对对象；有 Gurobi 就换 Gurobi |
| 新的 S5（K = ∞）与表 5 不同 | 成本更低 | 正常现象（K-模式解对全自适应模型可行）；表 5 的 S5 更新为新值，降幅相应重算 |
| 跨年份数据拿不到 | — | 用奇偶日划分（C3） |
