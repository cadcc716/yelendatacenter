## 一、最终能够被实验支撑的创新点（建议论文据此表述）

按证据强度排序。每一条都给出可直接引用的数据，以及不能越过的边界。

### 创新点 1：把"GPU 运行模式—液冷热安全温区—自然冷却能力"耦合约束纳入容量规划，两种机制存在超可加的正交互，使冷水机组可以取消

- **证据：**
  - 同一统一物理评价器下，完整耦合模型（M3）与静态基准（M0）相比：冷水机组 1573 → 0 kWth，能源相关年化费用 414.5 → 355.6 万元（**−14.2%**）。
  - 与工程常规做法（静态 32 ℃ 供液、按逐时气象和 ASHRAE 设计日校核）相比：冷水机组 1762 → 0 kWth，费用 417.8 → 355.6 万元（**−14.9%**）。
  - 交互项 $I_{GT}$ = **+25.7 万元**：单独热反馈（M2）只节约 1.9 万元，单独 GPU 调节（M1）节约 31.3 万元，二者叠加节约 58.9 万元。
- **机理：** 降频使实时任务的安全供液温度从 45 ℃ 提高到 50.2 ℃。最热小时的自然冷却可用系数因此从 0 变为正值，于是可以用单价只有冷水机组 1/4.3 的干冷器替代冷水机组。
- **边界：** 58.9 万元中约 56.4 万元来自光伏投资下降（GPU 休眠后负荷降低），这属于 GPU 调节的贡献。热耦合独有的贡献是取消冷水机组和交互项。**不能把全部节约归因于热耦合。**

### 创新点 2：容量规划与运行策略必须协同（同容量运行比较）

- **证据：** 设备都取 M3 的规划容量，只改变运行策略：
  - 完整耦合策略的年运行费用为 282.9 万元，是传统策略（593.1 万元）的约一半（−52.3%），实时 SLA 最高（99.94%）；
  - 按传统 25–32 ℃ 供液运行，有 35 个测试日无法安全运行（仅降频时为 30 天）；只升温不调节时，SLA 降到 98.13%。
- **意义：** 按耦合模型规划的设备若仍按传统方式运行，结果反而更差。这一点区别于"只做调度"或"只做规划"的研究，是全文证据最强的结论。

### 创新点 3：风险成本型条件分布鲁棒规划为罕见极端高温自动保留冷却储备

- **做法：**
  - 把失约以单价计入情景费用，形成风险成本型（软约束）两阶段规划；
  - 单价事先按经济含义设定（基准 $c_R$ = 100 元/GPU·h，敏感性 30 / 300）；
  - GPU 台数固定，只比较概率层（SP / U1 / U2 / U3）的差异。
- **证据：**
  - **SP 系统性低配，提高单价也纠正不了。** 设计日的经验概率为 0，最热训练日只有 1.8%。SP 在三种单价下都只配 1953–2026 kWth 自然冷却，比 DRO 少约 800 kWth。后果：
    - 设计日失约 880–1107 GPU·h（实时），另有约 3200–3500 GPU·h 的延期超时；
    - 72 h 真实热浪失约 744 GPU·h，DRO 为 183；
    - 年化冷却受限失约约 2550 GPU·h，DRO 为 402。
  - **DRO 用最坏分布把概率移向极端日。** U3 把设计日概率从 0 提到 0.098，把最热日从 0.018 提到 0.142，从而保留约 2840 kWth 自然冷却，不配冷水机组，设计日零失约。
  - **样本外风险调整费用：** U3 比 SP 低 1.2 / 15.6 / 58.7 万元/年（$c_R$ = 30 / 100 / 300）。
- **边界（必须如实写）：**
  1. 配对区块 bootstrap 的 95% 置信区间上界均约为 +6 万元，U3 更优的概率约 70%，**未达到 95% 显著**。原因是优势几乎全部来自测试集中唯一的热浪区块，设计日与压力测试只是确定性的佐证。
  2. DRO 的结果与"把设计日设为硬约束的 SP（M3）"相当，M3 反而略优 1.3 万元。DRO 的价值是**在风险成本框架下无需人为指定哪些情景必须硬保证**，而不是比精心设计的硬约束更省钱。
  3. 正负半方差（U3）相对对称（U2）只低 0.8 万元/年；软约束下无条件 U1 与 U3 相当，甚至略优 1.4 万元。**"非对称信息"和"条件化"在风险成本框架下没有独立价值**，论文不应把它们作为主要卖点。

### 创新点 4（支撑性，不宜作为主创新）：静态冷却设计的系统性偏差与安全风险

- 静态温水设计（M0-W45）账面费用低，但测试日冷却失约 920 GPU·h，设计日失约 5,552 GPU·h。
- 忽略 GPU 调节使光伏过配：M0 的复核光伏利用率只有 75%，M3 为 98%。

### 不能写入论文的说法

- "条件半方差 DRO 显著降本"：硬约束下各模型差异都在求解间隙内；软约束下相对 SP 的优势未达到 95% 显著。
- "正负半方差 / 条件化模糊集带来显著增益"：U3 相对 U2 每年只低 0.8 万元；软约束下 U1 与 U3 相当。
- "PUE 显著下降"：各方案 PUE 差异 < 0.002。
- "完整耦合同时提高高温安全性"：40 ℃ 热浪中 M3 失约 183 GPU·h，M0 为 78 GPU·h。
- "概率割平面算法提高求解效率"：小规模下比直接求解慢（1340 s 对 733 s）。

## 二、可能导致 Reject 或 Major Revision 的实质性问题（按严重程度）

严重程度分三级：
- **A**：可能直接导致拒稿；
- **B**：必须大修，否则难以接收；
- **C**：小修。

### A 级（拒稿风险）

**A1 研究对象与数据来源不一致；"样本外检验"不是真实的时间外推。**

- **问题：**
  - 算例以宁夏中卫为对象（电价、政策均取自宁夏），但逐时气象和光伏出力来自美国丹佛 TMY3。
  - TMY 是由不同年份"典型月"拼接成的合成年，按设计会弱化极端事件。在一个 TMY 年内按日期划分训练集和测试集，并不是真实的时间外推。
  - 测试集中的 40 ℃ 热浪只有 1 个片段，却承载了软约束 DRO 价值、M3 安全余量等关键结论。
- **审稿人会问：**
  - 中卫的结论为什么用丹佛的天气？
  - 只有一年合成数据，凭什么称"样本外鲁棒"？
- **修改：**
  1. 换用中卫或邻近站的多年逐时气象，例如 CSWD、中国气象局地面站或 ERA5 再分析资料，至少 10 年；
  2. 按年份做真实时间外推，例如用 2015–2021 年训练、2022–2024 年测试；
  3. 设计日采用中卫站的 ASHRAE 或 GB 50736 设计参数；
  4. 光伏出力用当地辐照重新计算。

**A2 负荷数据过短，且与气象人为配对，"联合不确定性"的说法不成立。**

- **问题：**
  - BurstGPT 只有 51 天，经过比例缩放后使用。测试集 95 天只对应 13 个不同的负荷日，平均每个重复约 7 次。
  - 负荷日与气象日按顺序人为配对，二者之间的相关性完全是人为的。
  - 条件模糊集只按季节分类，特征里的"负荷—气象联合"统计量没有物理意义。
- **修改：**
  1. 明确声明负荷与气象相互独立，把"联合不确定性"改为"负荷与气象两类独立不确定性的组合情景"；
  2. 改用更长的公开 GPU 负荷轨迹，例如 Azure LLM 推理轨迹（2023/2024）、Alibaba GPU 集群轨迹（cluster-trace-gpu-v2020/v2023），或多段拼接并说明处理方法；
  3. 报告负荷有效样本量，并对负荷日做区块 bootstrap。

**A3 创新归因不清，审稿人容易认为"节约主要来自服务器休眠这一已知技术"。**

- **问题：**
  - M3 相对 M0 节约 58.9 万元，其中约 56 万元来自光伏投资下降（休眠降低负荷），冷源投资只下降约 31 万元，运行费用反而增加 28 万元。
  - 服务器休眠或整合是已知的能耗比例化技术；若正文以"总节约 14.2%"作为核心卖点，审稿人会认为创新被休眠效应夸大。
  - 原稿的 M0 同时关闭了 GPU 调节和热反馈，容易被认为是"稻草人基准"。
- **修改：**
  1. 主表增加"节约分解"：光伏、冷源、运行三项，分别归因于 GPU 调节、热耦合和交互项；
  2. 把核心创新表述收敛为"耦合约束使冷水机组可取消 + 超可加交互项 + 规划与运行协同"；
  3. 正文加入本轮新增的工程常规基准"M0-设计工况"（静态 32 ℃ 供液 + 逐时气象 + ASHRAE 设计日）：冷水机组 1762 kWth，M3 相对它仍节约 62.2 万元（−14.9%）；
  4. 增加文献常用的"恒定 PUE / 固定冷却系数"基准，与 Zhang 2026、Xu 2027 等的建模假设对齐。

### B 级（必须大修）

**B1 决定核心结论的物理参数是反推值或设定值，未做稳健性检验。**

- **问题：**
  - 热阻 $R^{\rm th}$ = 57.1 K/kW 是由"700 W 满功率、45 ℃ 供液时恰好达到 85 ℃"反推的。各模式的安全供液温度（45 / 50.2 / 53 ℃）全部来自这一个标定点。
  - "冷水机组可取消"的结论取决于浅锁频模式在 50.2 ℃ 以下安全。
  - 休眠待机功率 0.03 kW、热备用比例 20%、主机分摊功率 0.467 kW 均为 C 级设定值。
  - 降频的功率—性能比例由 A100 实测结果移植到 H100。
- **修改：**
  1. 对 $R^{\rm th}$（±20%）、$T^{\rm chip,max}$（83–87 ℃）、$P^{\rm off}$（0.03–0.15 kW）、热备用比例 ρ（10%–40%）做敏感性分析，并画出"冷水机组容量为 0"成立的参数区域；
  2. 尽量引用 H100/H200 的实测功率—频率—温度数据或厂家资料。

**B2 冷却能耗模型的简化，使"气象—冷却"耦合在能耗层面不可见。**

- **问题：**
  - 干冷器风机单位电耗为常数，空气侧冷却按固定系数计算；空气侧电耗约占 IT 功率的 8.5%，比液冷侧冷源电耗还大。
  - 结果：M3 冷源电耗与日均温的相关系数为 −0.07，各方案 PUE 差异 < 0.002。
  - 题目强调热状态耦合，但能耗层面的收益几乎为零，审稿人会认为热模型只起到"容量约束"作用。
  - 模型也不含湿度（湿球温度），因此坦帕（湿热）的结果解释受限。
- **修改：**
  1. 风机功率按相似律随负荷率和逼近温差变化，并做分段线性化；
  2. 空气侧采用随气象变化的经济器 / 间接蒸发冷却效率；
  3. 至少给出这些改进对 PUE 和运行费用影响的敏感性分析。

**B3 软约束与原稿"硬性保证服务"的假设冲突，罚系数需要严谨依据。**

- **问题：**
  - 原稿假设（4）和式（29）的说明明确"不以主观违约罚系数代替服务约束"。
  - DRO 只有在软约束（风险成本）框架下才产生独立价值，因此必须改写建模假设。
- **修改：**
  1. 把硬约束模型作为罚系数趋于无穷时的极限情形，把风险成本模型作为主模型；
  2. 失约单价由 GPU 年化成本（约 10 元/GPU·h）、租赁价格（15–20 元/GPU·h）和 SLA 违约损失推导；
  3. 给出 30 / 100 / 300 元/GPU·h 的完整结果，说明结论在多大的单价区间内成立；
  4. 说明 GPU 台数由算力 SLA 决定、在风险成本模型中固定的理由。

**B4 求解质量不足以支撑部分数值比较。**

- **问题：**
  - 使用开源求解器 HiGHS，M2（15.3 万元）、U3（9.6 万元）、坦帕 M3（34.4 万元）、30% 样本量算例（34–38 万元）未收敛；κ 前沿为 30 min 结果。
  - **相对间隙具有欺骗性：** 目标函数中 GPU 投资约占 98%，15 万元间隙只相当于总目标的 0.08%，却相当于能源相关费用的 3.7%，与交互项和 DRO 差异同量级。
  - 局部搜索属于启发式，只能改进上界。
  - 原稿写"使用 Gurobi 求解"，与实际不符。
- **修改：**
  1. 用 Gurobi 或 CPLEX 复算全部主算例，把能源相关费用口径的间隙压到 0.5% 以内；
  2. 表格中报告"间隙 / 能源相关费用"；
  3. E5 的概率割平面在小规模下比直接求解慢（1340 s 对 733 s），应移到附录，不作为贡献。

**B5 储能、电网约束在全部算例中都不起作用。**

- **问题：**
  - 所有方案的储能容量都是 0，购电峰值约 3 MW，远低于 6 MW 接入上限。光伏平准化成本约等于谷价，导致光伏只配到午间自用规模。
  - 题目、摘要和模型中包含的储能、SOC、接入约束因此形同虚设，审稿人会质疑模型冗余。
- **修改（二选一）：**
  1. 加入宁夏大工业两部制电价中的容量（需量）电费，以及 2023 年新政中 ±80% 的尖峰/深谷电价，检验储能与 GPU 时移的互补作用；
  2. 从题目和贡献中删去储能，只作为模型的一般性组成部分说明。

**B6 关键结论依赖少量测试日，统计不确定性需要量化。**

- **问题：** 软约束 DRO 的优势、M3 的安全余量都集中在 6 月 24–30 日这一热浪片段。
- **修改：**
  1. 对 M3 与 M0、U3 与 SP 等全部主比较报告配对区块 bootstrap 的 95% 置信区间（本轮已对软约束 DRO 实现）；
  2. 多年气象数据到位后，按年份报告结论的稳定性。

**B7 代表日日内循环，跨日热累积只在压力测试中体现。** 液冷温度和储能 SOC 都按代表日首尾相等处理。应在正文说明这一简化，并以连续 72 h 压力测试作为补充证据（已有）。

## 三、创新是否真正落到模型中、模型是否缺项、实验能否证明贡献、结论是否越界

### 3.1 创新是否真正落到模型中

| 声称的创新 | 是否在模型中有对应约束 / 机制 | 判断 |
|---|---|---|
| GPU 运行模式 → 热安全 → 可用液冷温区 | 式（6）（7）的温区门控：模式 k 只能在 $T^{\rm w}\le T^{\rm chip,max}-R^{\rm th}h_k$ 的温区运行 | **已落实**，且是取消冷水机组的直接原因 |
| 液冷温区 → 自然冷却能力 | 式（8）$\phi_j$ 按温区下界与逐时气温计算 | **已落实**；但只影响容量，不影响风机电耗（$a^{\rm FC}$ 为常数），见 B2 |
| GPU 休眠 / 降频 → 负荷与散热 | 式（1）休眠态 + 热备用约束 | **已落实**；却是节约的最大来源，需与热耦合区分 |
| 液冷热惯性 | 式（4）液冷热容动态 | **部分落实**：温度轨迹在费用不敏感时段退化，热惯性的作用没有被单独量化 |
| 条件非对称 DRO | 式（30）模糊集 + 对偶重构 | **模型已落实，但效果没有落到结果中**：只有在风险成本（软约束）框架下才影响容量，非对称部分的增量很小 |
| 气象—负荷联合不确定性 | 情景按季节条件化 | **未真正落实**：负荷与气象人为配对，没有联合统计依据（A2） |

### 3.2 模型缺项（审稿人最可能指出的）

1. 风机、水泵功率随负荷率与温度变化；空气侧经济器。目前空气侧按固定系数计算，PUE 几乎不变（B2）。
2. 湿球温度与蒸发冷却。湿热气候（坦帕）的结论因此不可靠。
3. 休眠 / 唤醒的转换时间与能耗，以及热备用比例的服务等级依据（B1）。
4. 芯片热模型只有单点标定，没有热阻、热点温度的不确定性或稳健性检验（B1）。
5. 需量电费与两部制电价：储能在当前电价下没有作用（B5）。
6. 跨日热累积与储能状态衔接：代表日是日内循环，跨日效应只在压力测试中体现（B7）。

### 3.3 实验能否证明贡献

| 贡献 | 证明实验 | 证据强度 | 主要缺口 |
|---|---|---|---|
| 耦合使冷水机组可取消 | E1 消融 + 统一评价器 + 工程常规基准 | **强**（M0 / M3 均收敛） | 参数单点标定；气象为替代数据 |
| 超可加交互 $I_{GT}$ | E1 的 2×2 析因 | **中**（M2 间隙 15.3 万元） | 需商业求解器收敛 |
| 规划与运行协同 | 同容量运行比较 | **强** | 无 |
| 风险成本型 DRO 保留极端储备 | 表 4c / 4d、设计日、压力测试 | **中**：机理与确定性检验强，样本外统计不显著 | 测试集只有 1 次热浪；需多年真实气象 |
| 条件 / 非对称模糊集 | U1 / U2 / U3 对照 | **弱** | 增量 < 1 万元 |
| 概率割平面算法 | E5 | **不支持** | 比直接求解慢 |

### 3.4 结论是否超出数据支持范围

- **"总节约 14.2%"** 只适用于丹佛替代气象、BurstGPT 负荷和 C 级参数；必须注明，不能推广为"AI 数据中心普遍可节约 14%"。
- **"消除冷水机组"** 依赖浅锁频模式在 50.2 ℃ 以下安全这一反推值；在坦帕（湿热）气候中不成立（M3 仍需 1520 kWth）。必须写明适用气候。
- **"DRO 降低风险费用"** 只能表述为点估计和机理证据，必须同时给出置信区间与"单一热浪"的限制。
- **"联合不确定性"** 在负荷—气象人为配对的条件下不成立，应改为"独立不确定性组合"。
- **"PUE 降低" / "冷却能耗显著下降"** 不成立（差异 < 0.2%）。

## 四、最值得优先修改的 5 项（按投入产出排序）
