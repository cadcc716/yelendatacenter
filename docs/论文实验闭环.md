## 1 数据检索范围与获取限制（审稿时须如实说明）

1. **检索策略**：优先近 5 年顶会/期刊原文（ASPLOS'24、ISCA'24、HPCA'25、ASPLOS'25、KDD'25、Microsoft Research 2026）、标准与规范（ASHRAE 90.1-2019、ASHRAE TC9.9 液冷分级、PVWatts v5）、政府与行业机构数据（宁夏发改委、国家能源局西北监管局、国网宁夏电力信息公开、CPIA、CNESA/储能中标统计、NREL ATB），厂家公开数据表仅用于交叉验证。
2. **本次运行环境的网络限制**：会话网络策略只允许访问 GitHub、PyPI 与 microsoft.com。`arxiv.org`、`dl.acm.org`、`climate.onebuilding.org`、`re.jrc.ec.europa.eu`(PVGIS)、`power.larc.nasa.gov`、`open-meteo.com`、`srpnet.com`、`*.gov.cn` 等均被拒绝。因此：
   - 微软研究院的 3 篇 PDF（ASPLOS'24 功耗特性、Splitwise ISCA'24、AI 数据中心全生命周期 2026）为**下载原文核对**，可信度标为 A；
   - 其余数值来自检索引擎对原文的摘要/转引，可信度标为 B，投稿前应按表中来源逐项核对原文；
   - 工程设计值与由文献区间推导的标定值标为 C。
   如需补全，可在环境设置的 Network access 中放行上述域名后重跑 `data_prep.py`（设置方法见 https://code.claude.com/docs/en/cloud-environments#network-access）。
3. **气象数据的替代处理（重要）**：研究对象设定为"东数西算"宁夏中卫集群（电价、设备价格均为中国口径），但中卫站逐时典型年（CSWD/TMYx）文件无法下载。程序暂用**同属 Köppen BSk 半干旱温带气候**、海拔相近的 NREL TMY3 Denver Intl（725650）实测典型年作为替代气象（年均 10.9 ℃、光伏年利用 1526 h，中卫约 9–10 ℃、1500–1650 h）。这只能作为**方法验证算例**；正式投稿须将中卫 CSWD/TMYx EPW 放入 `data/raw/` 并执行 `python data_prep.py --epw <文件名>`，全部结果与图件会自动重算。
4. **负荷轨迹**：采用 BurstGPT（Azure 上 ChatGPT/GPT-4 服务的真实请求轨迹，KDD'25，GitHub 公开）。对话日志作为实时任务 R、API 日志作为可延期任务 B；仅保留真实日内形状与日间波动，按年均 500 / 200 GPU·h_nom/h 规模化（BurstGPT 官方说明允许按评测规模缩放请求率）。API 日志存在单日 0.1–104 M token 的极端突发，这是真实数据特征，未做平滑。
5. **GPU 型号说明**：参数基于 H100 SXM（文献数据最完整）。H100 受出口管制，国内实际部署可能为 H20 或国产加速卡；模型只依赖"模式—速率—功率—热阻"表，替换 `config.MODES/TDP/R_TH` 即可。

## 3 代码实现

### 3.1 程序结构

```

code/model.py         MILP 构建(式1–18)+HiGHS      code/run_all.py     场景/校验/样本外/敏感性/导出
```

### 3.3 求解策略与数值处理（论文"求解方法"小节可直接引用）

1. **DRO 精确重构**：式(17)对概率为多面体且非空（构造时断言 $\hat p\in\mathcal P_d$），内层 $\max_p$ 为 LP，按强对偶替换为对偶变量 $(\lambda_d,\alpha_d,\beta_d,\gamma^\pm_d)$ 的最小化，并入外层得到**单一 MILP**，无需 KKT 互补或列与约束生成迭代；SP（$p=\hat p$）与 RO（$\eta_d\ge C^{op}_{ds}$）为同一框架的特例。
2. **有效界收紧**：式(7)中大 M 取 $\min\{N^{max},A^R_t/v_k\}$（实时）与 $\min\{N^{max},\sum_{\tau\le t}A^B_\tau/v_k\}$（延期）。因 $p_{rk}>p^{sl}$，任何最优解都不会让多余 GPU 处于运行模式，故该界不切除最优解；收紧后 M3 求解由"300 s 间隙 9.3 万元"降至"281 s 间隙 0.2 万元"。
3. **间隙按绝对值控制**：总费用中 GPU 年化投资约占 96.4%，相对间隙 0.05% 即≈10 万元，会淹没能源侧差异。故设绝对间隙 1 万元（≈能源相关费用的 0.15%），表 T2 报告每个模型实际绝对间隙。
4. **DRO/RO 运行量重调度**：DRO/RO 目标只对最坏分布的支撑起作用，其余情景的运行量是退化的（例如首轮 RO 显示 72% 光伏利用率，属于假象）。按式(18)的定义 $Q_{ds}(x)=\min C^{op}_{ds}$，固定 $x$ 逐情景重新求解运行问题后再统计指标。
5. **储能互斥松弛**：$b$ 松弛到 $[0,1]$，校验"同时充放电时段=0"即说明松弛精确（本算例储能容量为 0，该约束不起作用）。
6. **样本外评估**：固定各模型容量，在与训练日不重叠的 123 个测试联合日上逐日求解运行 MILP；未满足工作量以松弛变量+大罚系数"优先满足"，缺额单独报告，不计入费用。分布偏移用指数倾斜 $w_i\propto\exp(\theta\,a^\top F_i)$ 加重高温/低光伏/高负荷日。

### 6.2 不同场景与 Baseline 的定量比较及机理

**(1) 规划结果被 GPU 投资主导，"总费用 −0.33%"不应作为主要卖点。** 七个模型 GPU 台数均为 2099，GPU 年化投资 18,657 万元/年，占总费用约 96.4%。机理：每台 GPU 年化约 8.9 万元，而降频带来的电费节省每台每年仅数百元量级（k2 相对 k1 每 GPU·h 少耗电约 12%，约 0.07 kWh），所以 GPU 数量只由"支持集中最紧张小时的实时+延期需求"决定，任何运行策略都无法换取更少的 GPU。论文应把评价口径放在**能源相关费用（光伏、储能、冷源年化 + 电费）**：M3/M4 较 Baseline 降低 8.9%/8.8%，冷源年化投资降低 73%–75%，冷却电量降低 40.8%。

**(2) 两项物理机制是互补关系，单独使用收益有限，叠加后出现质变。**
- 只加 GPU 调节（M1）：实时任务 66% 工作时长落在浅锁频、延期任务 30% 落在深锁频，IT 电量 −3.3%，冷却电量随之 −4.3%；但液冷温度被固定在 25–32 ℃，冷水机组容量只降 5%。原因是 N 按峰值配置后，非峰值小时有大量冗余 GPU，可用"多卡低频"替代"少卡满频"（能效 0.494 vs 0.560 kWh/GPU·h），但这只改变发热量，不改变散热路径。
- 只加热耦合（M2）：液冷温度可升至 45 ℃，自然冷却散热占比 68%→91%，冷却电量 −28.5%；但冷水机组容量只从 1517 降到 1255 kWth。原因是标称模式在 45.1 ℃ 以上不安全（式6），夏季最热小时 34.4 ℃ 时 45 ℃ 温区的可用系数 $\underline\phi=(38-3-34.4)/11.1\approx0.05$，冷水机组仍须按最热小时配置。
- 两者叠加（M3/M4）：降频使热点温升从 40.0 K 降到 34.8 K/31.9 K，安全温区上移到 50 ℃，最热小时 $\underline\phi=(45-3-34.4)/11.1=0.68$ 且自然冷却容量可放大，**冷水机组容量降为 0**，自然冷却承担 100% 液冷热量，PUE 1.250→1.230。这一"算力调节—热安全温区—自然冷却可用性"的链式耦合，正是式(6)(7)(8)的作用，也是本文最有说服力的创新点。

**(3) DRO 与 SP 的差异在本算例中很小，需要如实解释。** M4 与 M3 的最坏分布期望总费用相差 0.9 万元，小于两者的求解间隙（0.2 万/1.0 万元），可视为相等；M4 只是把自然冷却从 1946 增到 2115 kWth、光伏从 3083 减到 2950 kWp。机理有三：①有限支持 DRO 只能在已有情景上重新分配概率，而"每个支持点都必须可行"的硬约束已经把容量推到满足最紧张情景的水平，概率重分配只影响运行费用的加权；②各情景运行费用差异（12.4–20.5 千元/日）主要来自外生的负荷与光伏，受容量决策影响很小；③最坏分布 $p^*$ 把夏季概率从"低负荷日"移向"高延期负荷、较低光伏"情景（夏季 s=2 情景：0.115→0.428），因此 DRO 少配光伏、多配自然冷却，方向与直觉一致但幅度小。M5-RO 在本算例与 M4 几乎相同，也是同一原因。**论文不宜宣称"DRO 显著降低成本"**，而应表述为：在负荷—气象联合不确定下，所提有限支持矩 DRO 的最坏期望费用不高于 SP，且以约 0.005% 的经验期望代价换取对分布误设的保护；其价值随模糊集变大而上升（见敏感性 κ）。

**(4) 样本外评估揭示了比"概率误设"更重要的风险——支持集覆盖不足。** 测试集中出现 40.0 ℃ 高温日（训练情景最高 34.4 ℃）和 2177 GPU·h/h 的实时峰值（训练最高 1920）。结果：
- 冷水机组为 0 的 M3/M4 在 40 ℃ 日各出现 1937 GPU·h 实时任务缺额（实时任务要求温区≤50 ℃，此时 $\underline\phi=(45-3-40)/11.1\approx0.18$，自然冷却能力不足，热安全约束迫使 GPU 降载）；Baseline 因保留 1517 kWth 冷水机组，该日无缺额；
- 所有模型都因实时峰值超出 N 而出现缺额（Baseline 2148 GPU·h、14 个测试日）；
- M6 把训练集中最热日（36.7 ℃）等极端日加入支持集后，保留 841 kWth 冷水机组，**样本外缺额降至 755 GPU·h（比 M4 低 79%、比 Baseline 低 65%）**，40 ℃ 日缺额为 0，样本外运行费用仍比 Baseline 低 3.45%，代价是能源相关年费用比 M4 高 17.6 万元/年（662.5 vs 644.9 万元，相对 Baseline 的降幅由 8.8% 收窄到 6.3%）。
这说明：本文模型的可靠性主要取决于"支持集是否覆盖极端情景"，而不是矩约束的松紧。这是一个真实的、对审稿人有说服力的结论，建议在论文中作为改进方向和 M6 的设计依据。

### 6.3 不符合预期或需要说明的结果

1. **所有模型 GPU 台数相同**：由成本结构决定（见 6.2(1)），不是代码错误；若希望 GPU 调节影响 GPU 配置，需要引入"GPU 数量受供电/散热容量约束"或"按机柜功率上限部署"的约束，或采用租赁/分期价格口径。
2. **储能容量为 0**：宁夏峰谷价差小（平段交易电价 0.289 元/kWh，峰谷差≈0.289 元/kWh，与 2024 年 1 月公开统计的约 0.28 元/kWh 一致）。按 ±50% 浮动，每 kWh 储能每年套利收益上限约 72 元，低于其年化成本约 127 元；按 ±80% 浮动收益约 127.3 元，恰好与成本持平，因此储能只在高价差情景处于临界（见 T9）。这是合理的经济结论，不是约束缺失。
3. **M2 未在 900 s 内证明最优**（绝对间隙 10.6 万元），M6 间隙 20.5 万元：二者结论（冷水机组容量水平）稳定，但精细费用比较需以间隙为误差范围；使用 Gurobi/CPLEX 或延长时限可进一步收紧。
4. **光伏只配 2.9–3.2 MWp，利用率 97–98%**：光伏平准化成本约 0.225 元/kWh，而宁夏低谷（9–17 时）恰在光伏出力时段，低谷到户价 0.2365 元/kWh 与光伏成本几乎相等，故光伏只配到"午间自用不弃光"为止，属于价格结构驱动的合理结果。
5. **GPU 模式功耗数据为 A100 峰值功率降幅向 H100 平均功率的移植**（可信度 C），会低估 decode 主导负载的节能潜力，应以实测替换；液冷环路热容 30 kWh/K 对应 7 K 温区仅缓冲约 8 min 满负荷热量，热惯性作用有限（敏感性 C_W 验证）。
6. **气象为替代站点**：所有冷却相关数值须在替换中卫 EPW 后重算。

### 6.4 可以支撑的创新点（按证据强度排序）

1. **GPU 运行模式—液冷热安全温区—自然冷却能力的链式耦合使冷水机组可被取消**：M3/M4 冷水机组容量 0、冷源年化投资 −73%～−75%、冷却电量 −41%；而单独的 GPU 调节或单独的升温运行都做不到（M1 −5%、M2 −17% 冷水机组容量）。证据：表 T2、T4、T8，图 A2/A4/B1/B2/B3。
2. **两端点温区门控（式7）是保证热安全的必要条件**：所有耦合模型最高热点温度精确等于 85 ℃ 限值而不越限。
3. **有限支持矩 DRO 的单一 MILP 精确重构**：DRO 求解时间与 SP 同量级（409 s vs 281 s），并给出可解释的最坏分布（图 B6）。
4. **样本外评估揭示的"支持集覆盖"问题及极端情景扩充（M6）**：以能源相关费用 +2.7%（相对 M4）把样本外缺额降低 79%（图 B8）。该点建议作为讨论或扩展创新，而不是夸大 DRO 本身的作用。

## 9 局限与投稿前必须补充的工作

1. 用中卫 CSWD/TMYx 气象替换替代站点后重算（`--epw`）。
2. 按表中 B 级来源逐项核对原文；C 级参数（GPU 模式功率、等效热阻、COP 上限、环路热容、容量上限）需设备实测或厂家曲线标定。
3. GPU 模式数据建议以目标 GPU 在 vLLM/TensorRT-LLM 下实测 prefill/decode 的功率—吞吐曲线替换。
4. 支持集应纳入极端气象（如 ASHRAE 0.4% 设计日或气候变化情景）与极端负荷日（M6 思路），或改用连续支持的 Wasserstein DRO 作为对照。
5. 若要体现 GPU 调节对 GPU 配置的影响，应在模型中加入机柜/配电容量约束或采用租赁口径的 GPU 成本。
6. 使用商业求解器把 M2、M6 的间隙收紧到 1 万元以内。
