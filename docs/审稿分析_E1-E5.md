> 分析对象：`results/exp/`（v2：GPU 休眠态 + 10 液冷温区 + 统一设计负荷）。v1（5 温区、无休眠）的分析与结果归档于 `results/exp_v1_5温区/`。

## 一、总体判断

1. **物理一致性通过。**
   - 功率平衡、液冷热平衡、设备容量、任务完成全部满足，残差为 0。
   - 热点温度在测试日触及 85 ℃ 上限，热安全约束起作用。
2. **v1 指出的两个结构性问题已在模型中修正：**
   - 闲置基荷占 IT 电量 79%：加入 GPU 休眠态后，单位工作量 IT 电耗从 2.69 降到 1.52 kWh/GPU·h。
   - 5 温区按下界计算过于保守：改为 10 温区。
   这两项都是物理上有依据的建模改进，不是对测试集调参。修正后本文机制的收益明显放大。
3. **结论能否成立：**

| 命题 | 结论 | 证据强度 |
|---|---|---|
| 完整耦合显著降低能源相关费用 | **成立**：−58.9 万元/年（−14.2%），冷水机组 1573 → 0 kWth | 强（M0、M3 均收敛） |
| GPU 调节与热反馈存在正交互 | **成立**：$I_{GT}$ = +25.7 万元 | 中（M2 间隙 15.3 万元） |
| 规划与运行必须协同 | **成立**：同容量下 M3 策略运行费用 −52.3%，且无不可安全运行日 | 强 |
| 4 种气候均有收益 | **成立**：−5.5% 至 −14.2% | 中（坦帕间隙 34.4 万元） |
| 条件半方差 DRO 优于 SP / 对称 DRO | **不成立 / 不显著** | 只有"条件化优于无条件"和"建模不确定性优于确定性"成立 |
| 完整耦合同时提高高温安全性 | **不成立**：M3 在 40 ℃ 热浪中失约略多于 M0 | 见 3.4 |

## 三、不同方案与 Baseline 的定量比较及机理

### 3.1 E1：物理机制消融（统一评价器，同一 M3 运行控制）

| 方案 | 光伏 kWp | 自然冷却 kWth | 机械制冷 kWth | 测试日运行费用 | 能源相关费用 | 较 M0 | 冷却失约 GPU·h | 设计日失约 |
|---|---|---|---|---|---|---|---|---|
| M0 静态基准 | 3306 | 1651 | 1573 | 254.7 | 414.5 | — | 0 | 0 |
| M1 +GPU 调节 | 1665 | 1272 | 1494 | 283.7 | 383.2 | −31.3 | 0 | 0 |
| M2 +热反馈 | 3291 | 1416 | 1562 | 254.8 | 412.6 | −1.9 | 0 | 0 |
| **M3 完整耦合** | 1664 | 2821 | **0** | 282.9 | **355.6** | **−58.9（−14.2%）** | 105 | 0 |
| M0-W45 静态温水 | 3238 | 1837 | 0 | 254.9 | 376.2 | −38.3 | **920** | **5,552** |
| M3 无休眠 | 3199 | 3246 | 0 | 507.6 | 635.3 | +220.8 | 105 | 0 |
| M3 5 温区 | 1664 | 5000 | 21 | 281.7 | 366.9 | −47.6 | 105 | 0 |

**现象 → 原因 → 机制 → 差异：**

- **M3 的 −58.9 万元由三部分组成：**
  - 光伏投资 −56.4：GPU 休眠后 IT 负荷下降，光伏不需要配到 3.3 MWp。M0 按"GPU 全部常开"规划，在实际可休眠的运行下光伏利用率只有 75%（M3 为 98%）。
  - 冷源投资 −30.8：冷水机组 −37.2，自然冷却 +6.4。
  - 运行费用 +28.2：光伏减少后购电增加。
  
  **这说明两种机制贡献的来源不同。** 光伏规模的节约主要来自 GPU 调节（M1 已得到 −31.3）。取消冷水机组则只有两种机制叠加才能实现。论文应如实区分这两部分，不要把全部节约都归因于热耦合。
- **为什么单独机制都取消不了冷水机组：**
  - M1：GPU 可以休眠和降频，但 b=0 的静态冷却模型仍按 32 ℃ 设计供液、季节平均气温计算冷却能力，看不到"降频 → 可以升温运行"的价值，冷水机组 1494 kWth 基本不变。
  - M2：可以升温，但 GPU 全部常开、只有标称模式，45 ℃ 以上实时任务不安全，最热时段仍需冷水机组（1562 kWth），因此几乎没有收益（−1.9）。
  - 只有两者叠加，才能打开 45–50 ℃ 温区。实时任务安全温区升到 50.2 ℃，最热小时的自然冷却可用系数从 0 升到正值，于是可以用单价只有冷水机组 1/4.3 的干冷器替代冷水机组。
- **交互项 $I_{GT}$ = C(M1) + C(M2) − C(M0) − C(M3) = +25.7 万元 > 0**（规划目标口径 +26.3），机制解释与数值方向一致，是本文最有特色的定量证据。限制：M2 间隙 15.3 万元。M2 若存在更优解，$I_{GT}$ 会变大，因此 +25.7 偏保守。
- **规划模型偏差：** M0 规划模型估计的能源相关费用比统一复核高 67%。这主要来自运行控制的差异：M0 规划假设 GPU 全部常开，复核允许休眠。不能把它解读为"静态冷却模型的误差为 67%"。
- **M0-W45 的低成本是少服务换来的：** 测试日冷却失约 920 GPU·h，设计日失约 5,552 GPU·h。
- **M3 不是零风险：** 40 ℃ 测试日冷却受限失约 105 GPU·h。冷却修复需要自然冷却 +1157、机械制冷 +81 kWth，成本 8.3 万元/年；修复后仍比 M0 低 50.6 万元/年。
- **消融：**
  - 取消休眠态：+279.7 万元/年，是所有改进中最大的一项；
  - 5 温区粗化：+11.3 万元/年，自然冷却需配到 5000 kWth 安装上限。

### 3.2 同容量运行比较（容量统一取 M3，只改变运行策略）

| 运行策略 | 年运行费用（可运行日） | 实时 SLA | 实时失约 GPU·h | 不可安全运行测试日 |
|---|---|---|---|---|
| M0 策略（常开 + 标称 + 25–32 ℃） | 593.1* | 99.85% | 1,661 | **35** |
| M1 策略（休眠/降频 + 25–32 ℃） | 300.1* | 99.20% | 8,799 | **30** |
| M2 策略（常开 + 标称 + 温区控制） | 577.9 | 98.13% | 20,621 | 0 |
| **M3 策略** | **282.9** | **99.94%** | 650 | 0 |

\* 只统计可运行日，实际费用更高。

- **运行费用 −52.3% 主要来自 GPU 休眠。** M1 策略已降到 300.1，但有 30 天不可安全运行。
- **热状态控制的作用是保证可运行性。** M2 策略和 M3 策略都没有不可安全运行日。
- **两者缺一不可：**
  - 只做 GPU 调节、不升温：设备按高温运行设计（大干冷器、无冷水机组），若固定 25–32 ℃ 供液，夏季自然冷却能力为 0，导致 30 天不可运行；
  - 只升温、不调节：45 ℃ 以上只能停用 GPU，SLA 降至 98.13%。
- **结论：按耦合模型规划的设备必须以耦合方式运行。** 这是区别于"只做调度"或"只做规划"文献的关键论据，也是证据最强的结果。

### 3.3 E3：不确定性模型（全部训练数据）

| 方案 | 测试日运行费用 | 能源相关费用 | CVaR95 元/日 | 设计日失约 | 规划间隙 |
|---|---|---|---|---|---|
| U0 确定性均值 | 227.0 | 297.8 | 8,972 | **18,858**（仅 1209 台 GPU，SLA 96.8%） | ≤1 |
| U-SP 经验分布（=M3） | 282.9 | **355.6** | 10,700 | 0 | ≤1 |
| U1 无条件对称 | 282.0 | 365.9 | 10,650 | 0 | 18.6 |
| U2 条件对称 | 276.0 | 357.6 | 10,636 | 0 | ≤1 |
| U3 条件半方差 | 277.9 | 356.9 | 10,668 | 0 | 9.6 |

样本量实验（每月只用最早的 30% / 60% 训练日）：
- 60% 数据：三者都收敛，能源相关费用 355.4 / 354.8 / 354.9，差异 < 0.6 万元；
- 30% 数据：三者都只配 1947 台 GPU，间隙 34–38 万元，差异在间隙之内。

- **成立的结论：**
  - (a) 不建模不确定性代价极大：U0 低配 GPU，修复需新增约 968 台；
  - (b) 条件化优于无条件：U1 把全年情景合并，最坏分布可把概率移到与季节不符的高温情景，因此保留 576 kWth 冷水机组，能源相关费用比 U2/U3 高 8–9 万元。
- **不成立 / 不显著的结论：**
  - U3 相对 U-SP 在全部数据、60%、30% 三种样本量下都没有显著优势（能源相关费用差 −0.5 至 +3.2 万元，均在间隙内）；
  - 正负半方差（非对称信息）的独立价值未得到支持。
- **原因是结构性的：**
  - 运行可行性是硬约束，支撑集中的每个情景（含设计日）都必须可行，GPU 与冷源容量由最紧张的情景决定；
  - 概率层只改变期望运行费用的权重，而运行费用对容量不敏感；
  - 数据稀缺的真正风险是支撑集遗漏峰值情景（30% 数据时 GPU 低配），这要靠支撑集构造来应对，而不是靠概率层。
- **κ 前沿：** U2/U3 在 κ=2 时多配光伏、运行费用和 CVaR 下降、能源相关费用上升，方向合理。但 30 min 时限下间隙 10–20 万元，不宜讨论精确趋势。
- **论文表述建议：** "条件化有限支持模糊集提供可解释的最坏分布与稳健性校核，并优于无条件模糊集"，不宣称显著降本。若要让 DRO 体现价值，需要概率真正影响容量的机制，例如失约以期望代价进入目标（软约束）或热安全机会约束。

### 3.4 压力测试与设计日校核

- **ST2（6 月 25–27 日真实热浪，40 ℃）：**
  - 失约：M0 78 GPU·h（全部为 GPU 台数受限）；M3、U1–U3 183 GPU·h（其中 105 为 40 ℃ 当日冷却受限）；U0 3,258。
  - **这是对完整耦合不利的结果，应如实报告：** M3 不配冷水机组，以更低成本换来了更小的高温安全余量；8.3 万元/年的冷却修复即可消除。
- **ST1、ST3：** 除 U0 外均无失约。
- **热安全裕量：** 所有方案的最小裕量为 0–0.2 K，热安全约束在压力时段是紧约束。
- **ASHRAE n=20 年设计日（39.5 ℃）：**
  - 所有耦合方案（M3、U1–U3、无休眠、5 温区）均无失约；
  - M0-W45 失约 5,552、U0 失约 18,858 GPU·h。
  - 测试集最高温（40.0 ℃）略高于设计日，这是 M3 测试日仍有 105 GPU·h 失约的原因。

### 3.5 E4：适用边界

| 气候 | 机械制冷 M0 → M3 | 自然冷却 M0 → M3 | 能源相关费用变化 | M3 间隙 |
|---|---|---|---|---|
| 丹佛（基准） | 1573 → 0 | 1651 → 2821 | **−58.9（−14.2%）** | ≤1 |
| 芝加哥 | 235 → 0 | 5000 → 2500 | −32.0（−8.1%） | 10.6 |
| 坦帕（湿热，设计日 36.5 ℃） | 1704 → 1520 | 1679 → 1349 | −29.9（−7.3%） | 34.4 |
| 旧金山（凉爽） | 0 → 55 | 2227 → 1994 | −20.4（−5.5%） | 7.8 |

- **4 种气候 M3 均优于 M0，但节约的构成不同：**
  - 丹佛、芝加哥：冷水机组基本取消，冷源与光伏投资都下降；
  - 旧金山：M0 本来就不需要冷水机组，节约几乎全部来自光伏规模（GPU 调节效应）；
  - 坦帕：夜间也热，高温小时多，即使升温运行仍需大量冷水机组。坦帕间隙 34.4 万元，局部搜索与联合候选（如冷水机组 0–800 kWth 组合）都不可行，−7.3% 是可行解给出的保守值。
- **结论：** 热耦合的冷源收益在高温小时多、但夜间能降温的干燥气候中最大；在湿热或凉爽气候中，收益主要来自 GPU 调节。
- **其他敏感性：**
  - GPU 投资 ±40% 不改变任何配置（GPU 台数由峰值决定）；
  - 可延期任务占比 15% 时节约 14.3%；
  - 占比 50% 时，突发日需要的 GPU 超过机位上限，问题不可行。

### 3.6 E5：求解

- 小规模（6 情景）：概率割平面 3 次迭代收敛，与直接对偶 MILP 目标相差 0.34 万元（在 1 万元间隙内），验证了对偶重构的正确性；但耗时 1340 s，比直接法（733 s）慢。
- 中规模、全规模：直接法 30 min 仍有 38.4 / 10.0 万元间隙。
- **下界证明是瓶颈**，也是 U 系列无法精确排序的直接原因。

## 四、能够支撑的创新点（按证据强度）

1. **容量规划与运行策略必须协同。** 在"GPU 运行模式（含休眠）—液冷热安全温区—自然冷却能力"的耦合下：同容量时完整耦合策略运行费用 −52.3%，SLA 最高；按传统方式运行同一设备会出现 30–35 个不可安全运行日（3.2 节）。
2. **两种机制的正交互使冷水机组可以取消。** 冷水机组 1573 → 0 kWth，能源相关费用 −14.2%；$I_{GT}$ = +25.7 万元；单独热反馈几乎无收益（3.1 节）。
3. **把 GPU 休眠/降频纳入规划，消除了负荷与光伏的系统性过配。** 取消休眠态 +279.7 万元/年；M0 光伏利用率只有 75%（3.1 节）。
4. **静态或简化冷却设计的安全风险。** 静态温水设计在真实逐时气象下大量失约；设计日校核能发现测试集看不到的风险（3.1、3.4 节）。
5. **条件化的联合不确定性建模。** 条件模糊集优于无条件模糊集，确定性规划严重低配（3.3 节）。

**不能支撑、应删除或弱化的说法：**
- 条件半方差 DRO 相对 SP / 对称 DRO 显著降本或提高可靠性；
- PUE 显著下降（差异 < 0.002）；
- 完整耦合同时提高高温安全性（ST2 中 M3 失约多于 M0）；
- 把全部 −58.9 万元归因于热耦合（其中约一半来自 GPU 调节带来的光伏规模下降）。

## 五、修改建议

**必须修改（影响结论可信度）：**
1. 用商业求解器把 M2、U3、坦帕 M3 的间隙压到 1 万元以内，确认 $I_{GT}$ 与气候排序。
2. 用中卫 CSWD/TMYx 气象与其 ASHRAE 设计值重算。
3. 给出休眠待机功率、热备用比例的敏感性，或引用实测值（休眠态价值对其敏感）。
4. 自然冷却风机功率随逼近温差变化，使高温日冷却电耗不被低估。

**建议补充（增强创新性）：**
5. 增加储能起作用的场景（大峰谷价差、并网受限或需量电费），检验 SOC 约束与"算力—储能"互补。
6. 若保留 DRO 作为主贡献，引入能让概率影响容量的机制（失约期望代价或热安全机会约束）。
7. 加入冷水机组可变运维成本或启停约束，从模型上替代当前的平局打破项。
